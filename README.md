## 1. Project Objective

Hotel cancellations create uncertainty in room utilisation and revenue planning. This project develops a machine-learning workflow to estimate the probability that a hotel booking will be cancelled and then translates that probability into a cost-sensitive operational decision.

The project addresses two related questions:

1. How accurately can booking cancellations be predicted using information appropriate for a booking-time decision?
2. Under an explicit asymmetric error-cost assumption, what cancellation-probability threshold should be used instead of automatically using 0.50?

The project predicts cancellation risk. It does not directly optimise the physical number of rooms that a hotel should overbook.

## 3. Data Quality and Leakage Policy

Data quality and prediction-time feature availability are treated separately.

### Direct outcome leakage

The following variables directly reveal the realised booking outcome and are removed during cleaning:

- `reservation_status`
- `reservation_status_date`

### Booking-time feature exclusions

The following variables are retained in the general cleaned dataset for descriptive analysis but excluded before predictive modelling because they may contain information that develops after the original reservation:

- `assigned_room_type`
- `booking_changes`
- `days_in_waiting_list`

Therefore the final modelling workflow excludes all five leakage/suspect variables before model fitting.

Other cleaning decisions include:

- handling missing values
- removing 180 bookings with zero recorded guests
- removing one record with negative ADR
- retaining duplicate-looking bookings rather than automatically deleting them, because repeated booking records are not necessarily erroneous duplicates

## 4. Exploratory Findings

The cleaned data has an overall cancellation rate of approximately **37.08%**.

Selected observations from the exploratory analysis include:

- City Hotel cancellation rate: **41.79%**
- Resort Hotel cancellation rate: **27.77%**
- Non Refund bookings show a very high observed cancellation rate in this dataset
- cancellation behaviour varies across market segments and customer types
- longer lead time is positively associated with cancellation
- repeated guests have a lower observed cancellation rate than new guests

These are descriptive relationships and are not interpreted as causal effects.

## 5. Feature Engineering and Preprocessing

Engineered features include:

- `total_nights`
- `total_guests`
- `total_previous_bookings`
- `has_special_request`

The workflow uses an 80/20 stratified train/test split with:

    random_state = 42

The final split contains:

- 95,367 training observations
- 23,842 held-out test observations

Preprocessing required for model fitting is performed inside scikit-learn pipelines so transformations are learned from training data.

Rare country categories below 1% training frequency are grouped into `Other`.

Numerical and categorical variables are processed appropriately using scaling/encoding strategies required by the corresponding model family.

## 6. Models Compared

Five classification model families are evaluated:

1. Logistic Regression
2. K-Nearest Neighbours (KNN)
3. Decision Tree
4. Random Forest
5. Histogram Gradient Boosting

Model comparison uses **5-fold stratified cross-validation on the training set**.

Decision Tree hyperparameters are selected using training-only cross-validation with ROC-AUC as the tuning metric.

The held-out test set is not used for hyperparameter selection.

## 9. Cost-Sensitive Threshold Decision

Using 0.50 as the classification threshold is not automatically optimal when the two types of errors have different operational consequences.

For the decision analysis, the project uses the explicit illustrative cost assumption:

- False Positive cost = **2**
- False Negative cost = **1**

These are illustrative relative decision costs used for the project analysis; they are not measured hotel financial costs. Under this scenario, a false positive is assigned twice the cost of a false negative.

The threshold is selected using **5-fold out-of-fold predictions from the training data only**.

A sweep over thresholds from 0.01 to 0.99 gives:

**Recommended threshold: 0.61**

Training OOF minimum expected cost:

    13,458 relative cost units

The held-out test set is then used once to evaluate the already-selected threshold.

### Held-Out Comparison

| Decision Rule | Threshold | TN | FP | FN | TP | Precision | Recall | Expected Cost |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Default | 0.50 | 14,027 | 975 | 1,587 | 7,253 | 0.8815 | 0.8205 | 3,537 |
| Cost-sensitive | **0.61** | 14,419 | 583 | 2,125 | 6,715 | **0.9201** | 0.7596 | **3,291** |

Under the stated 2:1 cost assumption, the selected threshold reduces held-out expected cost by:

**246 relative units (6.96%)**

The threshold analysis is persisted in:

    results/threshold_sweep.csv
    results/decision_summary.csv
    results/figures/threshold_cost_curve.png
    results/figures/threshold_precision_recall_tradeoff.png
    results/figures/recommended_threshold_confusion.png

The 0.61 recommendation is conditional on the stated cost assumption; a different business cost ratio may produce a different optimal threshold.

Run the notebooks in numerical order from 01 through 08.

## 13. Final Conclusion

The project demonstrates that hotel-booking cancellation risk can be predicted effectively without relying on outcome leakage.

Among the five evaluated model families, **Random Forest achieved the strongest held-out performance**, with ROC-AUC **0.9584** and Average Precision **0.9406**.

The project then converts prediction into an explicit operational decision. Under the stated relative error costs of FP=2 and FN=1, training-only out-of-fold optimisation recommends a cancellation-probability threshold of **0.61** rather than the default 0.50.

On the untouched held-out test set, this decision reduced the defined expected cost by **6.96%**.

The recommended threshold should therefore be interpreted as a decision rule conditional on the project's stated cost assumptions, rather than as a universal hotel-industry threshold.
